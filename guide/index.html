Weights

Variable What it is When to use it
OCOMBWT The original survey weight best suited to diary-level analysis. This is usually the diary weight; where each person completed one diary, it is the person weight. MTUS does not change it. Transparency and replication
PROPWT OCOMBWT calibrated so that days of the week are balanced. Low-quality diaries (see BADCASE) get weight 0. Recommended for most analyses
PROPWT_ALL The same day-of-week calibration, but every diary keeps a positive weight, including low-quality ones. When you want to make your own decisions about diary quality

Diary Quality: BADCASE

Code Meaning Weight in PROPWT
0 Good-quality diary Kept
1 Age or sex missing 0
2 Day of the week missing 0
3 More than 90 minutes missing 0
4 Fewer than seven episodes 0
5 Two of the four basic activities missing (eating, sleep or rest, personal care, travel) Kept
6 Three or four basic activities missing 0
7 More than one of the above problems 0

Survey Design: PSU And STRATA

Where the source data allow, MTUS+ includes primary sampling units and strata for design-based standard errors. Declare the design before estimating, for example in Stata:

svyset psu [pweight = propwt], strata(strata)

PSU and STRATA are defined within each survey. The same codes in two surveys are different sampling units. A few surveys use replicate weights instead; MTUS+ does not yet harmonise these.

Combining Surveys

Pooling surveys and analysing them as one sample mixes differences in sample size, weight scales and sampling designs. The recommended approach has two steps:

  1. Estimate separately for each survey, using its own weights and design.
  2. Compare or combine the survey-level results with an explicit weighting scheme, for example equal weight per country or weights proportional to population.

Time Of Day

Minute 0 means a different clock time in different surveys: diaries start at different times, for example 04:00 in one survey and 06:00 in another. The diary start time is recorded in SVYSTART. Analyses that use clock time, such as sleep onset or daily rhythms, must be done within surveys, or after aligning all diaries to a common clock.

Simultaneous Activities

MTUS+ stores up to four activities per episode: primary, secondary, tertiary and quaternary. Primary activities add up to 1,440 minutes a day. Simultaneous activities do not add to this total automatically. Activities such as childcare are often done alongside something else, so primary-activity totals can understate them.

How many layers a diary allows depends on its design (see SVYNSIMS). Wide-interval diaries, common in LMIC surveys, allow several activities per 30- or 60-minute slot. More reported simultaneity can therefore reflect the instrument rather than behaviour.

Choose the time-allocation rule that fits your question. The timealloc command supports the common rules:

* All time to the primary activity
timealloc pri, did(did)

* Split time equally between primary and secondary activities
timealloc pri sec, did(did)

* User-defined shares, e.g. 60% primary and 40% secondary
timealloc pri sec, did(did) shares(60 40)

Building Daily Totals

The episode file is the source for diary-level totals in any classification or dimension. Examples:

* Daily totals in the CTUR 69-activity classification (like the legacy HAF)
timealloc pri_ctur, did(country survey svyregion hldid persid id)

* Daily time by location
timealloc eloc, did(country survey svyregion hldid persid id)

Episodes

For fully harmonised surveys, episodes follow the original diary. Episode counts and durations therefore differ partly because of instrument design. Before comparing episode-based measures across surveys, impose a common episode definition with epigenx, for example a new episode whenever pri_icat1 changes. epigenx can also reproduce the legacy MTUS episode definition. An R equivalent is in development.

Missing And Non-Harmonised Information

  • ICATUS and HETUS activities use system missing for unobserved activity. The CTUR 69-category variables use code 69.
  • Non-harmonised variables (original education and occupation classifications, income, migration, ethnicity or social group, religion, purpose, affect) are stored as text with their original labels. For legacy surveys (SVYPHASE = 0), some of these may still hold numeric codes stored as text.
  • The original diary fields OF1–OF12 have no fixed meaning across surveys. OF1 is not always the same kind of field. Their content is documented separately for each survey. To be confirmed: where the per-survey OF documentation will be published
  • Location, transport mode, setting and co-presence are filled only where the diary collected them. MTUS+ does not infer them from the activity. Harmonisation Policy

MTUS+ does not "correct" valid but inconsistent source responses. For example, a respondent reporting no children but giving a child's age is left as recorded. Users can apply their own cleaning rules. A small set of conservative, deterministic rules fills missing values only where other diary fields clearly imply them. These rules are documented in the Harmonisation and Quality Report. Please report suspected harmonisation errors to ctur@ucl.ac.uk.

Software

CTUR maintains Stata commands for time-use data. These include timealloc (time allocation and aggregation), epigenx (episode redefinition) and epitrans (wide-interval diaries to episodes). The general-purpose commands are on SSC as part of the timeuse package and are described in a Stata Journal article.
