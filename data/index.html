Overview Of The Files

File Level Description
MTUS+ Integrated File Episode The main MTUS+ product. It holds the complete episode sequence of every diary together with individual, household, diary and survey information, all harmonised activity classifications and the retained original diary fields.
MTUS+ aggregate file(s) Diary Derived files with diary-level time-use totals for common purposes. To be confirmed: which standard aggregate file(s) Release 1 will include. The User Guide proposes one based on ICATUS at 1-digit or 2-digit level.
Legacy HAF (Harmonised Aggregate File) Diary Legacy MTUS. One row per diary day, with background characteristics and predefined time-use totals.
Legacy HEF (Harmonised Episode File) Episode Legacy MTUS. One row per episode, using the traditional MTUS episode definition and a smaller set of background variables.
Unified legacy file Episode Legacy MTUS. The HEF episode structure combined with the HAF background information, so the two no longer need merging. To be confirmed: whether the HAF time-use totals are included

The Integrated File may also be distributed as country or regional subsets. These have the same variables and structure and contain fewer surveys.

To be confirmed: distribution formats (Stata .dta, .csv and/or Parquet), whether the largest files are split, and the file names

Why There Is No Single Aggregate File

The legacy HAF contained one predefined set of daily totals. That worked because MTUS relied mainly on a single activity classification. MTUS+ has several classifications, each at several levels of detail, and users may also want totals by location, co-presence or other diary dimensions. There is therefore no single natural aggregate file.

Detailed aggregates also need care. Where a source survey does not distinguish an activity, a detailed total can be zero even though the activity took place. MTUS+ therefore treats the episode file as the main source. Users build the daily totals they need with the timealloc command (see Using the data).

How Observations Are Identified

Each row of the Integrated File is one episode within a diary. Identifiers combine to identify each level:

Level Identifier variables
Survey country (or iso), survey, svyregion
Household + hldid
Individual + persid
Diary + id
Episode + epnum

hldid, persid and id are not unique on their own; always use the full combination. The variables hldid_name, persid_name and id_name record the names of the identifier variables in the source data, so records can be traced back to the original microdata.

What The Integrated File Contains

  • Identifiers and identifier names.
  • Survey-level variables (SVY*). These describe the design of each source survey (see below).
  • Individual characteristics. Demographics and partnership, employment, education, health and well-being, and other characteristics. The sex/gender variable now has a third category, other / non-binary. Most source surveys recorded only two categories. To be confirmed: whether the variable is called gender, as in the User Guide, or stays sex, as in the Codebook
  • Household structure. Variables derived from the household roster (see below).
  • Household characteristics. Geography, housing, assets and amenities, and economic resources.
  • Diary-level variables. Diary date, day of the week, diary characteristics and proxy reporting.
  • Weights. OCOMBWT, PROPWT and PROPWT_ALL, plus the diary-quality flag BADCASE. Also PSU and STRATA.
  • Episode-level variables. Timing and duration, plus:
    • activity in three classifications (ICATUS 2016, HETUS 2018 and the CTUR 69-category scheme), each for up to four layers: primary, secondary, tertiary and quaternary;
    • harmonised diary fields: location, mode of travel, co-presence, ICT use and enjoyment;
    • non-harmonised purpose and affect, kept as text;
    • original diary fields OF1–OF12, kept as text.

Full definitions are in the MTUS+ Codebook.

Survey-Level Variables

The SVY* variables take the same value for every observation from the same survey. They show differences in design that can affect comparisons.

Variable Describes
SVYREP Whether the survey sample is representative
SVYLIGHT Full or light diary design
SVYINTERVAL Diary reporting interval
SVYSTART Clock time at which the diary day starts
SVYMODE Mode of diary collection
SVYROSTER Whether a household roster is available
SVYANNUAL, SVYNMONTHS, SVYSEASON How fieldwork is spread across the year
SVYNDAYS Diary days required per participant
SVYMINAGE Minimum age for keeping a diary
SVYHHS How diarists are selected within the household
SVYNSIMS Number of simultaneous activity layers the diary allows
SVYELOC, SVYMTRAV, SVYCOPRES, SVYICT, SVYAFFECT, SVYPURPOSE Whether location, travel mode, co-presence, ICT use, affect and purpose were collected
SVYICAT*, SVYHETUS*, SVYCTUR How fully each activity classification can be represented for the survey
SVYPHASE Fully harmonised (1) or legacy under interim harmonisation (0)

To be confirmed: SVYPHASE is described in the User Guide, but it is not yet in the Codebook or the harmonisation template. The data to-do list also has an open item to add a transition-status variable.

Activity Classifications

Classification Variables (primary / secondary / tertiary / quaternary) Notes
ICATUS 2016 pri_icat1–3, sec_icat1–3, ter_icat1–3, quat_icat1–3 Detailed for work and production within the System of National Accounts boundary; suits cross-national and LMIC analysis
HETUS 2018 pri_hetus1–3, sec_hetus1–3, ter_hetus1–3, quat_hetus1–3 Detailed for leisure and personal activities; suits analysis focused on high-income countries
CTUR 69-category pri_ctur, sec_ctur, ter_ctur, quat_ctur Continuity with legacy MTUS

The digit gives the level of detail (1-, 2- or 3-digit). To be confirmed: the User Guide calls the 69-category variable MAIN69, while the Codebook uses pri_ctur. One name is needed.

Not every classification is equally complete for every survey. MTUS+ keeps a harmonised activity variable wherever a meaningful mapping exists, even if some categories cannot be identified. The SVY* coverage indicators show how complete each mapping is. Legacy surveys get their ICATUS and HETUS codes through interim crosswalks from the 69-activity scheme (see the Transition Guide). The 25-activity classification is kept only in the legacy files.

Missing activity. ICATUS and HETUS variables use system missing for an unobserved activity. The HETUS code 999 is recoded to missing. The CTUR 69-category variables keep code 69, "no activity reported". Handle this code explicitly when summing time across activities. Elsewhere in MTUS+, negative codes such as −6, −7, −8 and −9 distinguish types of missing information. To be confirmed: the definitive meaning of each negative missing code

Household Structure Variables

Where a household roster is available, MTUS+ reconstructs the generational structure of each household from members' ages, using an in-house algorithm. Generations and roles are inferred from ages and age gaps. They are not reported relationships.

Variable Description Status Roster needed
hhldsize Household size Existing
ngens Number of generations in the household New Yes
gen Generation the person belongs to New Yes
hhstruct Household structure (8 types) New Yes
hhrole Person's role within the household structure New Yes
minage / maxage Age of the youngest / oldest member Improved Yes
nchild Number of household members under 18 Improved
agech1–agech4 Ages of the 1st–4th oldest child, including adult children New Yes
agechN / agechNx Age / age group of the youngest child Improved
singpar Single-parent indicator Improved
hhtype, famstat Legacy household type and family status Legacy

Where available, hhstruct and hhrole are preferred to the legacy hhtype and famstat. The legacy variables are kept during the transition. To be confirmed: whether agech2 needs a household roster (the User Guide table marks it "X"), and the age-30 threshold for the youngest generation, which is under review

Episode Structure

For fully harmonised surveys, episode boundaries follow the original diary. A survey with a detailed classification therefore has more episodes than one with a broad classification. Episode counts and durations are not directly comparable across surveys until a common definition is applied with epigenx. Legacy surveys (SVYPHASE = 0) keep the legacy MTUS episode definition for now.
